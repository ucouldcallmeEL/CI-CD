# weather-app infrastructure (Terraform)

Scope of this repo: **infrastructure provisioning only**. App build/deploy and
the JTE pipeline definition itself are owned by the rest of the team; this
module is what their Jenkins "provision" stage calls (`terraform init/plan/apply`
against `infrastructure/`), and its output feeds their Ansible stage.

## Layout

```
infrastructure/
  main.tf                    # wires the modules together
  variables.tf / outputs.tf
  providers.tf                # aws + local providers, S3 backend stub
  terraform.tfvars.example
  templates/hosts.tpl         # Ansible inventory template
  modules/
    network/     VPC, 2 public subnets (2 AZs - required by the ALB), IGW, routing
    security/    3 security groups: alb, k8s-master, k8s-worker (see "Ports" below)
    compute/     1 master + N worker EC2 instances, IMDSv2, encrypted EBS, tagged
    alb/         ALB + target groups/listeners on the NodePort(s), attached to the workers
    inventory/   local_file provisioner -> writes ansible/inventory/hosts.ini
ansible/
  inventory/hosts.ini         # generated by `terraform apply`, do not hand-edit
```

## Design notes / decisions made

- **Modules over a flat config** so network, security, compute, ALB and the
  inventory generation can each be reasoned about (and reused) independently.
- **No manual provisioning**: everything, including the Ansible inventory
  file, comes out of `terraform apply`. The `inventory` module's `local_file`
  resource renders `ansible/inventory/hosts.ini` from the master/worker
  instance IDs and IPs produced by the `compute` module outputs - nobody
  copy-pastes an IP by hand.
- **Tagging**: every instance carries `Role = master` or `Role = worker`
  (plus a descriptive `Name`), so Ansible/other tooling can select on tags
  instead of hardcoded IDs if you extend this later.
- **ALB -> workers on NodePort**: `alb_sg` only accepts inbound on 80 from
  the internet; the worker SG only opens the NodePort range (30000-32767,
  configurable) to traffic **from the ALB's security group**, not the
  internet directly. Target groups/listeners are created per entry in
  `var.node_ports` (ports > 30000) and both worker instances are attached
  to each one.
- **Kubernetes-specific ports** (this is not a generic "2-tier web app" SG
  set - the security group rules are deliberately kubeadm-aware):
  - Master: `6443` (API server, from VPC + admin), `2379-2380` (etcd,
    VPC-internal, kept for future multi-master HA), `10250` (kubelet),
    `10259` (kube-scheduler), `10257` (kube-controller-manager), `8472/udp`
    (Flannel VXLAN overlay).
  - Worker: `10250` (kubelet, from master), `8472/udp` (overlay),
    NodePort range from the ALB SG only.
  - Adjust the overlay port if the Ansible playbook installs Calico/Cilium
    instead of Flannel.
- **Hardening applied**: IMDSv2 enforced (`http_tokens = "required"`),
  encrypted gp3 root volumes, SSH restricted to `var.admin_cidr` (never
  `0.0.0.0/0`), least-privilege SG rules per the port list above, an IAM
  role + SSM Session Manager policy on every node (so you have a
  break-glass path into the boxes that doesn't depend on the SSH SG rule
  at all), and a commented S3+DynamoDB remote backend stub in
  `providers.tf` for encrypted, locked state (point it at a bucket/table
  your team already owns, or provision those two resources separately
  before first `init`, since you can't apply into a backend that doesn't
  exist yet).

## Usage

```bash
cd infrastructure
cp terraform.tfvars.example terraform.tfvars   # fill in admin_cidr + key_name
terraform init
terraform plan
terraform apply
```

After apply, `../ansible/inventory/hosts.ini` exists and is ready for the
`kubeadm` playbook to consume - `[master]`, `[workers]`, and a
`[kubernetes:children]` group covering both.
